# fix/live-h1-gap — arm_worker 라이브 로더 H1 갭 수정

발견: 2026-07-29 (verify_today 오버레이 수정 회귀 준비 중 부수 발견)

## 증상

`arm_worker.make_live_loader` 가 `data_cache` 시드 + 거래소 **최근 200봉**을 이어붙이는데,
1h 에서 200봉 = 8.3일밖에 안 된다. 시드가 06-30 에서 멈춰 있어 그 사이가 통째로 비었다.

```
4h: 시드끝 06-30 20:00, 거래소 최古 06-25 20:00  → 갭 없음 (200봉=33일)
1h: 시드끝 06-30 23:00, 거래소 최古 07-20 19:00  → 갭 19일 21시간 ❌
```

**이 구멍은 매일 1일씩 커진다** — 시드 끝은 고정이고 거래소 창은 8.3일로 일정하기 때문.

## 영향 범위

- **`arm_worker` 만 해당.** `main.py` 는 H1 을 거래소에서 직접 `limit=H1_LIMIT` 로 받아
  (시드 merge 없음) 연속이다
- 지금까지 무증상이었던 이유: H1 refine 이 존 근처 최근 ±12봉만 본다 (`main.py:1046`).
  갭은 20일 전 구간이라 아직 닿지 않았다
- 즉 **현재 실피해는 확인되지 않았고, 잠재 위험이 커지는 상태**였다

## 수정

`get_full_klines_df`(기존 검증된 인프라)에 **시드 끝을 `since_ms` 로** 넘겨 페이지네이션으로
이어받는다. 시드가 아무리 낡아도 갭이 생기지 않는다(자가치유). 1h 1000봉=41일 → 통상 1페이지.

- 실패 시 기존 `limit=200` 경로로 폴백, 그것도 실패하면 시드만 사용 (기존 동작 보존)
- 갭이 남으면 조용히 넘어가지 않고 `⚠️ {sym} {tf} 갭 N개 잔존` 경고 출력

## 파리티 검증 (`parity_h1gap.py`)

9심볼 무장존을 **구(200봉) / 신(시드연결) 로더로 각각 완전 재계산**해 비트 비교.
trade-log 재활용 없음 — 후보생성부터 재실행.

```
갭:  구 17개 → 신 8개

        심볼     구무장     신무장      동일   구only   신only
   ADAUSDT       1       1       1       0       0
   BTCUSDT       7       7       7       0       0
   XRPUSDT       1       1       1       0       0
   (나머지 6종 0/0)
------------------------------------------------------------
        합계       9       9       9       0       0

✅ 무장존 비트동일 — 갭수정이 진입판정을 바꾸지 않음
```

**비트동일의 의미**: 갭이 지금까지는 진입판정을 망가뜨리지 않고 있었다는 실측 확인.
즉 이 수정은 **과거 판정을 바꾸지 않으면서 미래 위험만 제거**한다. 무손실 배포.

## 잔여 갭 8개 — 별건 (이 브랜치 범위 밖)

시드 parquet 자체의 구멍. SOL·XRP 에서 **4h·1h·두 코인 모두 날짜가 동일**하다:

```
2022-02-25 → 2022-03-01  (3일 4시간)
2022-03-31 → 2022-04-03  (2일 4시간)
```

거래소 중단이면 전 종목에 나타나야 하는데 2종만 뚫린 것으로 보아 **최초 시드 수집 시
fetch 실패**로 추정. 4년 전 워밍업 구간이고 **백테도 동일 parquet 을 쓰므로 파리티는 유지**된다.
고치려면 시드 재수집 + 백테 전체 재검증이 필요 → 별도 판단 사항.
